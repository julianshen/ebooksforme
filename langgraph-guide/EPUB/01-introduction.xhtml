1.2 什麼是 LangGraph？

LangGraph 是 LangChain 團隊開發的低階 Agent 編排框架。簡單來說，它讓你用「畫圖」的方式來設計 AI 的工作流程。

一句話理解：LangGraph = 狀態機（State Machine）+ 圖論執行引擎 + 持久化記憶

1.2.1 為什麼需要 LangGraph？

想像你在設計一個 AI 客服系統：

場景純 LangChainLangGraph
用戶問簡單問題✅ 直接回答✅ 直接回答
需要查資料再回答⚠️ 容易出錯✅ 明確步驟：查資料 → 分析 → 回答
用戶中途改問題❌ 從頭來過✅ 從上次狀態繼續
執行到一半當機❌ 全部重來✅ 從 Checkpoint 恢復
需要人工確認❌ 很難實現✅ Human-in-the-loop 內建支援

「沒錯！而且這個『大腦』是你可以自己設計的。」

1.2.2 LangGraph vs LangChain

很多人搞混這兩個。簡單來說：

  • LangChain：工具箱（Tools、Models、Prompts、Memory）
  • LangGraph：藍圖（怎麼把工具組合成有邏輯的工作流程）

「LangChain 是食材，LangGraph 是食譜！」——小語

1.3 核心概念：Graph、State、Node、Edge

LangGraph 的世界由四個基本元素組成：

1.3.1 Graph（圖）

整個工作流程就是一張有向圖（Directed Graph）。每個節點（Node）做一件事，每條邊（Edge）決定下一步去哪。

from langgraph.graph import StateGraph, START, END

# 建立一張圖
graph = StateGraph(dict)

# 加節點
graph.add_node("hello", lambda state: {"message": "Hello!"})
graph.add_node("world", lambda state: {"message": state["message"] + " World!"})

# 加邊
graph.add_edge(START, "hello")
graph.add_edge("hello", "world")
graph.add_edge("world", END)

# 編譯
app = graph.compile()

# 執行
result = app.invoke({})
print(result)  # {'message': 'Hello World!'}

💬 小語的筆記

「所以 Graph 就像一張地圖，Node 是景點，Edge 是路線。START 是起點，END 是終點。簡單！」

1.3.2 State（狀態）

State 是整張圖的共享記憶體。每個節點都可以讀取和修改 State。

from typing import TypedDict

class MyState(TypedDict):
    count: int
    message: str

def add_one(state: MyState):
    return {"count": state["count"] + 1}

def make_message(state: MyState):
    return {"message": f"Count is {state['count']}"}

graph = StateGraph(MyState)
graph.add_node("add", add_one)
graph.add_node("msg", make_message)
graph.add_edge(START, "add")
graph.add_edge("add", "msg")
graph.add_edge("msg", END)

app = graph.compile()
result = app.invoke({"count": 0})
print(result)  # {'count': 1, 'message': 'Count is 1'}

關鍵理解：State 是不可變的！每個節點回傳的是「更新」而不是直接修改。LangGraph 會自動合併這些更新。

1.3.3 Node（節點）

Node 是圖中的工作單元。它可以是：

  • 一個 Python 函數
  • 一個 LangChain Runnable
  • 另一張子圖（Subgraph）
  • 一個 Tool 呼叫
# Node 可以是任何 Callable
def my_node(state):
    # 做點什麼...
    return {"result": "done"}

# 也可以是 LangChain 的 Runnable
from langchain_openai import ChatOpenAI
llm = ChatOpenAI()
graph.add_node("llm", llm)  # LLM 本身就是一個 Node！

1.3.4 Edge（邊）

Edge 決定控制流（Control Flow）。LangGraph 有兩種邊：

類型語法用途
普通邊add_edge("A", "B")A 做完一定去 B
條件邊add_conditional_edges("A", router)A 做完根據條件決定去哪
def router(state):
    if state["score"] > 0.5:
        return "good"
    else:
        return "bad"

graph.add_conditional_edges(
    "judge",
    router,
    {"good": "celebrate", "bad": "retry"}
)

「就像選擇題：分數高就慶祝，分數低就重來！」

1.4 第一個完整範例：簡單的問答機器人

讓我們做一個會查維基百科的問答機器人：

from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI
from langchain_community.tools import WikipediaQueryRun
from langgraph.prebuilt import ToolNode

# 定義 State
class QAState(TypedDict):
    question: str
    context: str
    answer: str

# 工具
wiki = WikipediaQueryRun()
tools = [wiki]
tool_node = ToolNode(tools)

# LLM
llm = ChatOpenAI()
llm_with_tools = llm.bind_tools(tools)

# Node：理解問題
async def understand(state: QAState):
    response = await llm_with_tools.ainvoke([
        ("system", "You are a helpful assistant."),
        ("human", state["question"])
    ])
    return {"answer": response.content}

# Node：執行工具
def execute_tools(state: QAState):
    return tool_node.invoke(state)

# 條件：是否需要工具？
def needs_tool(state: QAState):
    last_msg = state.get("messages", [])
    if last_msg and hasattr(last_msg[-1], "tool_calls"):
        return "tools"
    return END

# 建圖
graph = StateGraph(QAState)
graph.add_node("understand", understand)
graph.add_node("tools", execute_tools)
graph.add_edge(START, "understand")
graph.add_conditional_edges("understand", needs_tool, {"tools": "tools", END: END})
graph.add_edge("tools", "understand")

app = graph.compile()

# 執行
result = app.invoke({"question": "什麼是 LangGraph？"})
print(result["answer"])

💬 小語的興奮

「哇！它真的去查了維基百科然後回答我！而且整個流程清清楚楚：理解問題 → 決定要不要查資料 → 查資料 → 再理解 → 回答。不像以前亂七八糟的！」
