第 4 章：Pregel 執行引擎

「原來 Pregel 是這樣運作的！」——小語

4.1 Pregel 是什麼？

Pregel 是 LangGraph 的執行引擎。它負責：

  • 按照圖結構執行 Node
  • 管理 Channel 的讀寫
  • 處理並行執行
  • 支援 Checkpoint 和恢復

名字由來：Pregel 是 Google 的圖計算框架名稱（用於 PageRank）。LangGraph 借用這個名字，因為它也用「圖的迭代計算」模型。

4.2 Pregel 執行模型

Pregel 使用Superstep（超步）模型：

# Pregel 執行循環（簡化版）

class Pregel:
    def invoke(self, input, config):
        # 1. 初始化 State
        state = self._initialize(input)
        
        # 2. Superstep 循環
        while True:
            # 2.1 找出當前可執行的 Nodes
            ready_nodes = self._get_ready_nodes(state)
            
            # 2.2 並行執行這些 Nodes
            updates = self._execute_nodes(ready_nodes, state)
            
            # 2.3 合併更新到 State
            state = self._apply_updates(state, updates)
            
            # 2.4 檢查是否結束
            if self._is_finished(state):
                break
        
        return state

4.2.1 Superstep 詳解

每個 Superstep 包含三個階段：

階段動作原始碼位置
1. 讀取每個 Node 讀取自己關注的 Channel 值pregel/_read.py
2. 執行並行執行所有 ready 的 Nodepregel/_algo.py
3. 寫入將 Node 回傳寫入對應 Channelpregel/_write.py

💬 小語的理解

「所以 Pregel 就像一個『回合制遊戲』：每回合（Superstep），所有準備好的角色（Node）同時行動，然後更新遊戲狀態（State）。」

4.3 原始碼深度解析：_algo.py

_algo.py 是 Pregel 的核心算法：

# langgraph/pregel/_algo.py（簡化版）

def apply_writes(
    channels: dict[str, BaseChannel],
    writes: list[tuple[str, Any]],
) -> None:
    """將所有 Node 的寫入應用到 Channel。
    
    這是 Superstep 的『寫入階段』核心。
    """
    # 1. 按 Channel 分組寫入
    grouped: dict[str, list] = defaultdict(list)
    for channel_name, value in writes:
        grouped[channel_name].append(value)
    
    # 2. 對每個 Channel 執行 update
    for channel_name, values in grouped.items():
        channel = channels[channel_name]
        channel.update(values)  # Channel 自己決定如何合併

4.4 並行執行機制

Pregel 如何決定哪些 Node 可以並行？

# 判斷 Node 是否 ready：所有輸入 Channel 都有值

def is_node_ready(node, channels):
    for trigger in node.triggers:
        if not channels[trigger].is_available():
            return False
    return True

# 每個 Superstep 開始時，找出所有 ready 的 Node
ready_nodes = [n for n in nodes if is_node_ready(n, channels)]

# 並行執行（使用 ThreadPoolExecutor 或 Asyncio）
with ThreadPoolExecutor() as executor:
    futures = [executor.submit(n.run, state) for n in ready_nodes]
    results = [f.result() for f in futures]

關鍵：Node 之間沒有資料依賴時才能並行！如果 Node B 需要 Node A 的輸出，它們會在不同 Superstep 執行。

4.5 本章總結

  • ✅ Pregel 是 LangGraph 的執行引擎，使用 Superstep 模型
  • ✅ 每個 Superstep：讀取 → 並行執行 → 寫入
  • ✅ _algo.py 負責核心算法：apply_writes、get_ready_nodes
  • ✅ 並行執行由 Channel 依賴關係決定
