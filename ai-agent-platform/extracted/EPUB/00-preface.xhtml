前言

為什麼寫這本書

2025 年，當我第一次看到 Manus AI 自主拆解任務、啟動多個 Agent 協作完成複雜工作時，我意識到一個新時代的到來。不是因為它的技術有多前衛，而是因為它揭示了一個被長期忽視的事實：單一 Agent 的時代已經結束，多 Agent 協作才是未來。

但隨之而來的是一連串問題：

  • 如何讓不同能力的 Agent 安全地協作？
  • 如何確保一個 Agent 的錯誤不會拖垮整個系統？
  • 如何評估一個 Agent 的品質是否足夠投入生產？
  • 如何在 Kubernetes 上高效地運行數百個 Agent？

這些問題沒有現成的答案。Google 的 Gemini Enterprise Agent Platform (GEAP) 提供了一個企業級的參考框架，但他們的實作細節大多閉源。開源社群有 ADK、A2A、MCP 等協定，但缺乏系統性的架構指導。

這本書試圖填補這個空白。

這本書適合誰

這本書不是入門教程。我假設你已經：

  • 熟悉 Kubernetes 和容器化部署
  • 了解 NATS 或類似的訊息系統
  • 有過建構分散式系統的經驗
  • 對 AI Agent 的概念有基本認識

如果你正在：

  • 設計一個類似 Manus 的多 Agent 平台
  • 評估如何將 Agent 投入生產環境
  • 研究 Google GEAP 的開源替代方案
  • 探索 Agent 沙箱隔離的最佳實踐

這本書就是為你寫的。

這本書的結構

我按照 Google GEAP 的四層架構來組織這本書：

BUILD（建構層）：如何設計和開發 Agent，包括 ADK 框架選型、A2A 協定實作、MCP Tool Registry。

SCALE（擴展層）：如何讓 Agent 在生產環境可靠運行，包括 Agent Runtime、Session 管理、Memory Bank、Sandbox 隔離。

GOVERN（治理層）：如何確保 Agent 的安全與合規，包括 Identity、NetworkPolicy、Agent Gateway、審計追蹤。

OPTIMIZE（優化層）：如何持續提升 Agent 品質，包括 Evaluation Framework、可觀測性、Prompt 優化。

每一章都遵循相同的模式：問題 → 設計原則 → 實作方案 → 程式碼範例 → 常見陷阱。

關於思維模式

這本書的寫作深受 Boris Cherny 的影響。他在《Programming TypeScript》中展現了一種我深以為然的技術寫作風格：

先理解問題的本質，再給出解決方案。

他不會直接告訴你「怎麼做」，而是先讓你理解「為什麼要這樣做」。這種由內而外的教學方式，能讓讀者真正掌握技術的核心，而不是死記硬背配置。

在這本書中，我會盡力效仿這種風格。每一個設計決策背後，都會有清晰的推理過程。每一行程式碼，都會解釋它解決了什麼問題。

程式碼與範例

書中的所有程式碼都是真實可執行的。核心系統使用 Go 實作（因為我們需要編譯型語言的效能和容器化友好性），Orchestrator 使用 Python ADK（因為它提供了最完整的 Agent 開發體驗）。
